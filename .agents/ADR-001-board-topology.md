# ADR-001: 棋盘地图拓扑与数据结构

- **状态**: 已确认 (Accepted)
- **日期**: 2026-07-10
- **决策者**: 用户 + WorkBuddy
- **来源**: `/grill-with-docs` 会话，目标让《暴富》地图贴合《大富翁4》观感

---

## Context（背景）

现有实现（`scripts/board/board.gd` + `data/boards/full_board.json`）：

- 单一闭合 `Curve3D`（圆角矩形 80×60，9 个控制点）
- 40 格按 `position ∈ [0,1)` 比率均匀撒在曲线上
- 相机跟随棋子
- 与《大富翁4》不符：真实大富翁4 地图是**网格上的路网**，可斜走/曲折、贴合真实地形（台湾/大陆/日本/美国），且 jail/hospital 是主环外的死胡同分支。

用户确认的目标形态：

1. 总体拓扑是**环**，但能斜向/曲折，增加空间丰富度
2. 能贴合真实地图形状（数据驱动，未来多地图：台湾/大陆/日本/美国）
3. 带**死胡同分支**（jail/hospital 等），仅事件送入，平时绝不从主环误入
4. 保持 40 主环格（正式版）
5. 相机跟随棋子
6. 渲染可见道路

---

## Decision（决策）

采用 **「网格路网 + 单向主环 + 事件死胡同分支」** 模型。

### 1. 棋盘 = 网格上的路网

- 棋盘是一个 `grid_cols × grid_rows` 的网格，每格 `cell_size` 米（默认 **2.0m**，角色约 1.6m 高，格比角色稍大）。
- 世界坐标推导：`world(col,row) = (col*cell_size, 0, row*cell_size)`。**不手填 x,z**。
- 只有"路格"才通车；其余格是空地/建筑/装饰。路网 = 有序主环 + 若干分支链。

### 2. 主环 = 单向有序序列

- `loop[]` 按绕行方向排序（index 0..N-1）。
- 相邻主环格**可正交也可对角相邻**（对角相邻 = 斜向道路，仅当数据显式如此设计时才成立）。
- 主环是**单向环**：正常绕行方向固定；转向卡使其反向绕行（仍沿同一环，只是反向）。
- 主环上**不会出现四岔路**（每格最多连 prev/next 两格）。

### 3. 分支 = 事件死胡同

- 特定主环格（接入点 junction）挂一个 `branch` 指针，指向一条死胡同链（1~N 格）。
- 仅当事件（入狱/就医等）触发时，token **传送**到分支末端；平时绝不从主环走入。
- 逃脱条件满足后，token **传送回接入点**，并**维持进入分支前的 heading**（沿原方向继续绕环）。
- 接入点因此最多是**三岔路**（prev / next / branch），但 branch 不是常规前进选项。

### 4. 移动与 heading

- token 持有 `heading`（8 向之一，或直接用"环上前/后"表示）。
- 正常步进：`i → (i+1)%N`（reverse 卡时 `i → (i-1+N)%N`）。
- 每步若相邻格是斜对角，则这一段是斜向道路（视觉沿对角路面走）。
- 路口无需复杂逻辑：主环每格前进方向唯一（环序决定）；唯一的三岔在接入点，而分支不计入常规前进。

### 5. 渲染

- **可见道路**：在相邻路格之间渲染路面/街道（支持正交与对角两种路面）。
- 棋子沿路网移动（贴着路走，斜线处沿对角路面）。
- 相机：跟随当前棋子（沿用现有 CameraRig 方案）。
- 材质：unshaded（沿用）。

### 6. 数据驱动 / 多地图

- 单张地图 = 一个 JSON 文件（结构见 `board-data-schema.md`）。
- 先做**小原型**验证系统（见下），后期通过换 JSON 扩展到大型/真实地形地图，无需改代码。

### 7. 土地-道路绑定机制 (Land-Road Binding)

> **修正**：建筑不应建在角色走过的道路上。道路格只负责"通行 + 触发"，土地（归属/等级）是路旁独立对象。

- **道路格 (Road Tile)**：`loop[]` 中的格都是道路格，是 token 实际走过的格。其 `type` 决定"落到此格触发什么事件"：`start`(领钱) / `chance`(抽卡) / `fate`(命运) / `bank`(银行) / `transport`(车站) / `property`(触发地产) / `jail`·`hospital` 接入点等。
- **土地 (Land Plot)**：独立对象，只记录**归属权 (owner) 与等级 (level)**，以及价格/租金/升级费/分组等静态数据。**不落在道路上**，渲染在环路**外侧**的相邻格。
- **绑定 (Binding)**：道路格用 `land_id` 指向 `lands[]` 中的土地；token 落到带 `land_id` 的道路格时，对该土地执行"购买 / 收租 / 升级"逻辑。
- **绑定基数**：
  - 普通住宅用地（1×1）：**1 道路格 ↔ 1 土地**（1:1）。
  - 特殊商业用地（2×2，如商业区/保险公司）：对应 **2 个相邻道路格**共享同一 `land_id`。
  - **拐角格无土地**：环路拐角必须是特殊地点（`fate` / `news` / `bank` 等），不绑土地。
- **位置**：土地在 `lands[]` 中显式写 `(col,row)`（数据驱动，贴合真实地图）；作者约定摆在环路**外侧**。2×2 用地以锚点 + `size:2` 占外侧 2×2 格。
- **渲染**：建筑（含等级高度）渲染在**土地格**上，不在道路格；道路格只渲染路面。

## Prototype（原型规格 · 含土地绑定）

用于验证系统的最小可用棋盘：

- 网格 **8×8**，`cell_size = 2.0`
- 主环 **12 格**（每边 3 格的小方环）
- 其中若干为 **property 道路格**，各有 `land_id` 指向 `lands[]`（住宅 1:1 / 商业 2 路共享）
- 拐角格为 `fate`/`bank` 等特殊地点（无土地）
- 1 个 **jail** 分支（接入点 1 格 + 死胡同 1 格）
- 1 个 **hospital** 分支（接入点 1 格 + 死胡同 1 格）

## Open parameters（数据可调，非架构决策）

- 主环格数（原型 12，正式 40，未来可更多）
- 分支数量与类型（jail / hospital，可扩展 lottery 等）
- 对角路出现位置（由数据决定）
- 网格总规模（原型 8×8，未来 28×28+）

## Consequences（影响）

- **数据模型变更**：`BoardTile.position: float` → `BoardTile.col, BoardTile.row`（或 `pos: Vector2i`）；新增 `branch` 字段。
- **土地/道路拆分**：新增 `LandPlot` 数据模型（owner/level/price/rent/...）与 `lands[]` 数组；`loop[]` 中的 property 道路格通过 `land_id` 绑定，自身不含归属/等级。
- **board.gd 变更**：`_build_path_from_tiles` 的圆角矩形硬编码删除，改为从 tiles 坐标构建主环 `Curve3D`（含对角段）+ 每分支独立 `Curve3D`。
- **回合引擎**：移动逻辑从"沿曲线 ratio"改为"环序索引 + heading"，接入 EventBus 的 `branch_entered` / `branch_exited` 信号；落到 property 道路格时经 `land_id` 触发土地逻辑。
- **tile_view.gd**：地板尺寸由 4×3 改为 2×2；道路格只渲染路面；**建筑渲染在土地格**（外侧），按 `level` 显示高度。
- **测试**：现有 `test_board_data` 需更新（position→col/row），新增分支/对角/heading/土地绑定测试。

---

## Migration（迁移路径）

1. 改 `BoardTile` 数据模型（col/row + branch + land_id）
2. 新增 `LandPlot` 数据模型 + `lands[]`
3. 改 `BoardData.load_from_file` 解析新 JSON（loop + lands + branches）
4. 改 `board.gd` 路径构建（坐标→Curve3D，含对角）
5. 加道路渲染 + 土地格建筑渲染（外侧）
6. 改回合引擎移动为环序 + heading，接 `land_id` 触发
7. 接分支事件（branch_entered / branch_exited）
8. 更新 GUT 测试（含土地-道路绑定）

## Topology 示意（ASCII）

```
        (row 0)  L L   L     L . .     L=土地(外侧, 只记归属/等级, 建筑渲染在这)
        (row 1)  S-1-2-3-J . . .     S=start  3=接入点J(jail branch)
        (row 2)  |           |       J 挂死胡同: J→[JAIL]
        (row 3)  |           |
        (row 4)  |           |       H=接入点H(hospital branch)
        (row 5)  9-8-7-6-H . .        H 挂死胡同: H→[HOSP]
        (row 6)  . . . . . . . .
                  (col→)
   道路格(loop[]): S(0)-1-2-3-J(4)-5-6-H(7)-8-9-10-11-S   ← 单向绕行, token 走这
   土地(lands[]): 1↔L 2↔L  6↔L(商业2路共享)  ...          ← 路旁独立对象, land_id 绑定
   对角路:   在 loop[] 中相邻元素 Δcol==Δrow==±1 时自动成立
   分支:     仅事件送入 JAIL / HOSP，逃脱回 J / H 并维持原 heading
   拐角:     3/6 等拐角格为 fate/bank 等特殊地点, 无土地
```
