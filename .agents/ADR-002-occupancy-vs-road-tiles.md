# ADR-002: 道路放置物（occupancy）与「道路格不建实体」

- **状态**: 已确认 (Accepted)
- **日期**: 2026-10-20
- **决策者**: 用户 + Qoder
- **来源**: PLAN §四 的 P5、§七「occupancy 与『道路格不建实体』的冲突」一行；AGENTS.md 硬约束第 4 条
- **适用**: P5 的路障／地雷／定时炸弹；P6 的神明刷出与恶犬；P12 小偷搬动放置物。道具栏、载具、遥控骰子、乌龟卡不在本 ADR 的范围

---

## Context（背景）

P5 要往路上放东西，而它们与已有的「格上状态」不是一类：

- **点券箱**（`coupon.rs`）的全部状态是「这一格第几回合重新长出来」，一个 `HashMap<TileIndex, u32>` 就够。
- **路障／地雷**有「谁放的、还在不在、被谁清掉」；
- **定时炸弹**还会从「躺在格子上」变成「附在人身上」，带着 38 步计时换主人；
- P6 的神明要随机刷在普通道路格上，踩到就附身；P12 的小偷会把路障／地雷／宝箱偷走。

这些是**带身份与生命周期的个体**。把它们塞进资源里的 `HashMap`，等于在资源里手搓实体生命周期：谁 despawn、谁换 key、谁在存档时复原，每个使用者都要自己补一遍。

与此同时，AGENTS.md 硬约束第 4 条仍然成立：**道路格不建实体**，拓扑真相只在 `BoardDef`/`ActiveBoard`。本 ADR 划的就是这两句话的边界。

---

## Decision（决策）

### 1. 一句话

**occupancy 是挂在主环格坐标上的运行时实体；拓扑真相仍然只在 `BoardDef`/`ActiveBoard`；道路格本身依旧不建实体。**

PLAN 里写的 `TileOccupancy` 就是这里的 occupancy，落地时不要建第二套名字。

### 2. 实体形状

一个放置物 = 一个核心实体，挂：

```text
Occupancy { kind: OccupancyKind, at: OccupancyAt }
Gameplay                                  // 回主菜单随其它核心实体一起清
```

`at` 是**一个状态字段**，不是两个可以并存的组件：

```text
OccupancyAt::OnTile(TileIndex)                 // 路障/地雷/宝箱/神明在棋盘上
OccupancyAt::Carried { by: Entity, steps_left } // 定时炸弹附身
```

为什么是枚举而不是 `PlacedAt(TileIndex)` + `CarriedBy(Entity)` 两个组件：后者能写出「既在地上又在人身上」的矛盾态，而所有读取点都得再加一条 `Without` 才能把矛盾挡回去。位置是排他的，就让它只能表示一个值。

坐标键用 **`TileIndex`**，不是 `GridPos`：主环之外（监狱／医院死胡同）没有主环下标，结构上就放不了东西 —— 「在监狱里放路障」这种数据写不出来，不需要额外的校验。

### 3. 拓扑边界（不可越过）

occupancy **不**：

- 不新增 `TileKind`，不进 `landing::domain_of()` 的穷尽表；
- 不改变 `walk_path` 的纯函数形状，不参与相邻判定；
- 不在 `ActiveBoard` 里建 `HashMap<TileIndex, Entity>` 之类的第二份索引；
- 不给道路格 spawn 一个「格子实体」再往上面挂子实体。

`ActiveBoard.lands` 是「土地运行时状态 → 实体」的索引；occupancy 全场只有个位数，按组件查询就够。加索引就是第二份真相，得在 spawn/despawn/清场/读档四处同步，漏一处就是「看到的东西和能踩到的东西不是同一个」。

**放置物实体不是道路格实体**：它没有 `TileDef` 的副本；一个格子的静态属性（类型、绑定的地、分支）永远回 `BoardDef` 查。

放置物挂在**道路格**上，不挂在土地上：一块 2×2 商业地绑两个道路格，挡掉其中一个入口不等于挡掉另一个。土地只有归属/等级/抵押这些运行时状态，没有「路上有什么」。

### 4. 一格一件（10-20 拍板）

一格主环道路上最多一个 occupancy。

- 所有产生与移动路径 —— 道具放置、P6 神明刷出/自行换格、宝箱刷出、P12 小偷搬动、P15 读档读回 —— 走**同一个** `occupancy::place`/`move` 闸门，它查 `occupancy_at(tile)`，目标格已有就拒绝或换格；旧格在同一笔里空出来。
- **同帧两条请求不能都读到「空」**：`Commands::spawn` 是延迟写，两条同帧放置同一格的请求会各自通过检查，落成两件 —— 与 P3d③ 抵押那条「同一帧押两遍钱」是同一个坑。闸门要么把请求串行处理并维护一个帧内的「本帧已占格」集合，要么走就地写入；不要只靠「spawn 完再查」。读档/批量刷出也走同一笔。
- 因此**不需要同格结算顺序表**：「路障旁边还躺着一颗地雷」这种组合写不出来。
- 定时炸弹被拾起后 `at = Carried`，原来那一格空出来，可以再放别的。
- 「一格一件」只管**在地上**的；被携带的炸弹不占格。
- **槽位**（一格一件）是数据不变式：`place`/`move` 只查 `occupancy_at(tile)`。**玩家主动放置**另有一条合法性：目标格没有玩家棋子；「视窗范围内」是表现层的镜头判据，不进 core —— AI 与 headless 测试没有视窗，照样能放。
- **读档与 P6 神明换格不走「无人」这条**：路障把某人挡在它那一格之后，「人站在路障上」是合法状态，读档不能被玩家放置的合法性拒掉。槽位仍然一格一件，两者分开判。

### 5. 触发口径（10-20 拍板）

| 种类 | 何时触发 | 结果 |
|---|---|---|
| 路障 | **经过**（进入即停） | 本次行走在路障格终止；路障不消耗；该格按静态 `TileKind` 照常结算 |
| 地雷 | **经过** | 本次行走就地终止；毁载具；`detain(Hospital, 3)`；地雷消耗 |
| 定时炸弹 | **经过**拾取；之后每走一步计数 | 拾取改 `Carried`；第 38 步爆炸；3×3 建筑降 1 级（保所有权）+ 住院 5 天 |
| 宝箱／礼物盒 | **落脚**（走完骰子停在那格） | 拾取；路过不给 |
| 神明／守护神 | **落脚** | 附身（转成 P6 的 `Possession`）；路过不给 |

新增种类必须在**穷尽表**里表态，不允许默认。P6 的恶犬到时候按同一条表填。

这张表说的是**玩家这一步踩到了什么**。P6 的神明自己走动、走到玩家所在格，是另一个方向的事件；它算不算附身由 P6 单独拍，不要偷偷复用这张表。

### 6. 路障的「停」怎么实现（10-20 拍板）

- 停在**路障格**，不是前一格。
- 掷骰入队时就把 `walk_path` **返回的路径**截断到第一个路障（含该格）：`walk_path` 本身仍是纯拓扑函数，不认识 occupancy。
- 因为「停在路障格」且放置闸门拒绝「有玩家的格子」，**不存在「一步都走不了」的零进度分支**。唯一的例外是传送把某人放到路障格上，而他下一回合可以直接离开（离开不触发路障）。
- 路障**不消耗**：PLAN 原文是「挡所有人（小偷例外）」。小偷的穿越是 P12 的 passability 判据，不在本 ADR 落地。

> 后果：路障格若是某人的地产，被挡住的人会照常付租／触发购买。这是「按静态格型结算」的直接推论，不是漏写。

### 7. 行走接缝：必须能半路停下

地雷与定时炸弹爆炸时，**后面的步数一步都不该走**。所以：

- `walk_step_system` 在推进每一步时读 occupancy；遇到「触发即停」的种类，**在走步循环内部**清空剩余路径并停止。不能先把剩余 `TileStepped` 发出去，再让一个后置 reader 补账 —— 那样表现层会先看见棋子走完，再被告知它其实在医院。
- 停下时发 `WalkHalted { player, tile, cause }`，**不发** `PlayerArrived`；被炸到的那一格**不结算静态 `TileKind`**（不买地、不收租）。清空路径不能靠「`path.is_empty()` 就发 `PlayerArrived`」判别 —— 中断时队列同样是空的，但语义相反；两只出口必须分开。
- **中断必须把 `TokenPosition.tile` 改回停下的那一格**。B2c 的「掷骰即落定终点」只在走完全程时成立；地雷在第 2 步炸掉，逻辑位置若还停在原来算出的第 5 格，下一回合、租金、渲染、存档会一起错。`WalkQueue` 的进度与表现层的插值也以停下那一格为准。
- 落脚触发的种类以 **`PlayerArrived.to`** 为准，不以「最后一个 `TileStepped`」为准 —— 中断时两者不是同一格，而且中断的那一格本来就不该触发落脚效果。
- 落脚触发的种类由 `PlayerArrived` 的 core 侧 reader 在行走后处理；`TileStepped` 继续照发给表现层做动画，两条 reader 各有游标，不互抢。银行的 ATM 资格已经是 `TileStepped` 读法的先例（`grant_atm_access_system` 读 `TileStepped`，路过与停下都算）。
- **走步循环只做「与移动有关」的事**，后果不进循环：
  - 循环内可以**就地改**占用物的移动相关状态 —— 炸弹的 `steps_left`、`Carried.by`、路障截断 —— 因为它们决定后面几步还能不能走；拾取发生在第 2 步、38 步在本次行走内走满，都不能等走完再补。
  - 住院、拆房、毁载具、钱与点券的入账这些**后果**，由 `resolve_occupancy_system` 在停下后应用。它改的东西不影响「停在哪」，所以可以等。
  - 与落格分派「域 system 推不动回合」同一条分工：谁决定位置，谁就只决定位置。

### 7.1 步数与落点的口径

- `DiceRolled.steps` **永远是骰面原值**，不因路障截断或乌龟卡夹步而改变（与 P4④/乌龟卡那条口径同源）。
- 路障截断在**掷骰入队时**发生：`WalkStarted.to`、`TokenPosition.tile` 与 `WalkQueue.path` 都取截断后的终点，不是骰子算出来的原终点。路障格本身在路径里，正常到达并结算。
- 地雷/炸弹的中途中断发生在**行走时**：`WalkStarted.to` 只是计划终点，实际落点以 `WalkHalted.tile` 为准；两者不同不是数据错误。

### 8. 定时炸弹的两相与转让

- **拾取**：`OnTile(tile)` → `Carried { by, steps_left }`。同一个实体，不 despawn 再重 spawn —— 身份保留，转让、动画、存档都跟着同一条走。
- **计数**：只数「走路进入的格」。传送、出狱回接入点、保释回家都不动它。计数口径（拾取那一步算不算第 1 步）在 P5 的测试里钉死，本 ADR 只决定它住在实体上。
- **相遇**（10-20 拍板）：佩戴者行走路径中**经过另一名玩家当前所在格**即相遇；不额外算相邻格。顺序回合下这是唯一可观测的「同格」，两人不会同时移动。
- **转让**自动：改 `Carried.by`，不问、不挂 `Pending`。
- **爆心是 `TileIndex`**，3×3 按网格切比雪夫距离算，不是按 `LandId`。`Books::damage` 仍只吃 `LandId` 集合，所以 P5 要在 `plot`/`BoardDef` 上补一个「以格为中心 3×3 命中哪些地块」的纯函数；不要在炸弹模块里另写一份范围算术（`PlotArea` 已经是地块坐标系的唯一一份）。命中住院的玩家集合也按同一 3×3 网格取（含携带者）；已经在拘留中的人交给 `detain` 的「更久的那一张赢」，不另写分支。
- **爆炸后**实体 despawn。

### 9. 传送不触发

只有「行走的每一步」算踩到。卡牌传送、出狱回接入点、保释、命运/机会的 `move_to` 都**不触发** occupancy（也不触发地雷／宝箱）。P7 的传送机与 P12 的绑架复用这一条。

### 10. 清场、清空与存档

- **宽范围夺地清场**：只读 `LandDamage::sweeps_tile_state(area)`（P2 已定形）。P5 用不到（定时炸弹只降层、不夺地）；P11/P12 落地时按受影响地块绑定的道路格清，事件格上的放置物要不要清由那一步决定，但**不要**在各道具里重写一遍判据。
- **存档**：occupancy 进 `GameSnapshot`（P15），记录 `kind` 与 `at`（tile／carrier／steps_left）。存档里引用玩家用 `PlayerId`，不是 `Entity`。实体模型不等于不序列化。
- **清场**：所有 occupancy 带 `Gameplay`，回主菜单随其它核心实体一起清；新局默认空盘。开局即送的是玩家背包里的道具，不是地上的放置物。

### 11. 表现层

- core 的 occupancy 不带 `Transform`；`game_app` 观察 `Added<Occupancy>` / `RemovedComponents<Occupancy>` 自己 spawn/despawn 图标或模型，与土地同一套流程。
- `Carried` 状态的视觉挂在棋子上，换人时跟着换。
- `NM_DUMP` 加一栏「道路放置物」，用于截图核对。

## Consequences（影响）

- P5 的五条验收各有一个 `game_core` 测试；其中三个必然绕不开本 ADR 的边界：
  - 路障截断到自身格，且该格静态结算照常，`TokenPosition` 落在路障格；
  - 地雷在走步循环里中断，后续 `TileStepped` 一条都不发、地雷格不结算、`TokenPosition` 改回地雷格、不发 `PlayerArrived`；
  - 炸弹在路径经过另一名玩家所在格时转让，且被携带时不占原格。
- 结构测试义务：`place` 闸门拒绝一格第二件；新局清空；`TileIndex` 结构上排除死胡同格（分支格没有下标）；落脚触发读 `PlayerArrived.to`，中断时不会误触发脚下那格。
- 新增消息 `WalkHalted`。
- 走步循环多一个 occupancy 查询，并负责炸弹计数/拾取/转让这些「决定还能不能走」的状态；后果结算另起一段。
- `TileStepped` 的读者从表现层一个变成「表现层 + core（ATM、落脚 reader）」多个，各自游标。
- **不做**：不建道路格实体；不做第二份索引；不在 `domain_of` 里加分支；不把点券箱迁进 occupancy；不在本 ADR 管道具栏、载具、遥控骰子、乌龟卡。

## Rejected alternatives（被否掉的方案）

- **`HashMap<TileIndex, State>` 资源**：点券箱那种「一格一个标量」够用，但定时炸弹的附身／38 步／换主人／被偷需要身份；塞进 map 等于手搓实体生命周期，还会让同一套「路上的东西」分裂成两个机制。
- **一格多件 + 同格顺序表**：可行，但用户 10-20 拍了一格一件；模型、渲染、存档都因此更简单。
- **路障停在前一格**：需要一条「零进度不重结算」的例外；停在路障格把这条例外消掉了。
- **相邻格也算相遇**：炸弹会变成「路过一次连传多人」的逃亡游戏；用户选了「经过对方那一格」。
- **每个种类各开一个资源**：路障一个 map、地雷一个 map、炸弹一个 map —— 同一条「路上有什么」的查询要问三次，P6/P12 再加两次。

---

## 维护提醒

- 新增一种道路放置物时，必须同时决定三件事：**占不占格**、**经过还是落脚触发**、**会不会被 P12 小偷搬走**。三个问题各有一张表在等它。
- 任何「走几步」相关的改动（载具、遥控骰子、乌龟卡）都不要再写一个走路循环；它们改的是入队前的步数，本 ADR 的走步循环仍是唯一一份。
- 本 ADR 与 `damage::sweeps_tile_state` 的裁决是两条独立的口径：一条说「夺地时清不清」，一条说「放置物是什么」。P11 落地时两条都要读，不要合并成一条 `if`。
