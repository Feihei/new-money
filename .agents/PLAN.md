## 一、口径先钉住

《大富翁4》的实际形态和「回忆起来的样子」有几处系统性偏差，这几条直接决定要不要造某个东西：

| 常被当成 4 代的 | 4 代实际 | 对本项目的结论 |
|---|---|---|
| 机会卡 + 命运卡双牌堆，随机抽 | **没有「机会」**。命运格是**一条 32 项的固定顺序循环表**（不是洗牌），且**多项条目按交通工具分支**；另一张独立格是**新闻中心** | `Chance`/`Fate` 双牌堆保留作本项目的《暴富》设定，但**两张池子都改成定序**（§四 P3）。新闻是第三个系统，独立成阶段（P11） |
| 神像是格子 | 神明**随机刷在普通道路格上**，踩到即附身 | 不加 `TileKind::GodShrine`，走 P5 的 occupancy |
| 拍卖行是格子 | 拍卖是**事件机制**（拍卖卡／魔法屋法术／**新闻**／破产变卖） | 不加 `TileKind::Auction` |
| 踩法院被判刑、税务局收税 | 4 代**取消了法院与税务局格**，查税由**查税卡**执行（强制 20% 现金） | 不加 `TileKind::Court`/`Tax` |
| 天气/季节 | **4 代没有** | 不做 |
| 经过起点领薪水 | **4 代没有**（那是 Monopoly 桌游的 $200）。固定进账＝月末 10% 储金利息 + 每月 15 号三项分红 | `TileKind::Start` 维持现在「什么都不发」是对的，别顺手补薪水 |
| 角色有个人特技 | **4 代角色无特技**，只有 AI 三档性格 | 与 [CHARACTERS.md §八](./CHARACTERS.md)「角色不带规则分支」一致 |
| 物价指数上限 6 | **上限 6 是手游《4 fun》**；PC 原版无上限（玩家刷到 107 万后整数溢出） | 不加上限，按 PC 口径 |
| **「变卖所有卡片道具」是随机新闻** | 它是**命运第 20 条**（固定序）。把它说成新闻的是 2026 年的内容农场文 | 归命运池 |
| **外星人袭击** | **拆两半，且我 10-16 早先的判决错了一半（用户实报后翻案）**：「**被外星人绑架 3 天**」确有（游戏内状态枚举，出现在「谁能参与拍卖」的排除名单里，有日本图实战复盘佐证）；「外星人攻打地球、一排房屋消失」我按孤证否掉了 —— 那是错的，见下面那条 | 绑架＝离场类效果（P4 建模 / P11 接线）；拆房那一档进 §三 的**建筑损害阶梯** |
| 陨石 / 地震 / 台风 / 洪水 / 怪兽 | **原判「孤证所以不做」判据不成立**：公开文本记不住 ≠ 游戏里没有，而 2012 逗游那份清单把「**外星怪兽袭击，摧毁房屋一栋**」与「**外星人攻打地球，一排房屋消失**」列成**两条不同条目、两种不同范围**——内容农场造不出这种区别，玩家记住的恰恰是那个区别。**怪兽**在 4 代另有硬出处：30 张卡表里的**怪兽卡**（指定一块地建筑夷为平地）与**恶魔卡**（整路段夷为平地），效果与你说的「仅拆建筑、所有权保留」完全吻合；8 代只是把它从卡片改成了新闻事件。陨石仍查无实据 | 见 §三 的**建筑损害阶梯**：深度 × 归属 × 范围三个维度，**只有三种合法组合，三个都有硬出处**，存疑的只是事件名挂在哪一格 |
| **点券格子（道路上 10/30/50）** | 4 代对应物是路上随机刷的**点券箱／宝箱／礼物盒／守护神**，**一次性拾取**。本项目拍板做成**固定格** | 见 §五 |
| **小游戏格子（打气球／接财宝／企鹅挖宝）** | 4 代对应物是**游乐场格**，三种小游戏赚点券。官方文本与地图详解两处名字不一致（接金币／射神明／猜兔子 vs 打气球／企鹅挖宝／喜从天降） | 名字用本项目三种，不追求 4 代同名 |

术语：「点券」＝第二货币，与 `Wallet.cash` 完全分离，**永不通兑**（已拍板）。理由：通兑等于「用钱买道具」，P5 放置类的平衡会当场崩，且 4 代点券本来只能靠游乐场与宝箱挣。

#### 建筑损害阶梯（10-16 补，用户实报后翻案的产物）

你回忆的那套东西不是四条零散效果，是**三个维度**：深度（降层／归零）× 归属（保留／夺地）× 范围（一栋／3×3／路段／9×9／全图）。**深度与归属只组成得出三种合法组合**，我上一版列的「整排消失变无主」和「大范围归零变无主」其实是**同一格只差范围**（外星人 vs 核弹都是夺地归零），那一版把范围错当成了档位。

| 深度 ＼ 归属 | **保留所有权** | **夺地（变无主）** |
|---|---|---|
| **降 N 层** | ✅ 飞弹「威力 3×3、**房屋下降一级**」；✅ 恶魔附身「所经降一级（空地不拆）」 | **这一角不该存在**：地都收了还留层做什么。类型上就不给这个开关 |
| **归零** | ✅ 怪兽卡「彻底摧毁一座大厦」（一栋）；✅ 恶魔卡「整路段夷为平地」；✅ 工程车「所经之地拆成空地」 | ✅ 命运#4 **强制征收**：房屋同灭、土地收回（一栋）——**这一条有 5 个镜像老攻略互相一致、还带序号可核对**，所以「夺地」这一维根本不是孤证；✅ 核子飞弹「房屋摧毁**至无人占领**」（9×9～全图，原文连"神与物品全部消失"一起清）；⚠️ 山洪爆发"土地流失"、外星人攻打地球"一排房屋消失"：档位对得上，**只有事件名与范围核对不了** |

三个合法组合全部有硬出处，唯一存疑的只是「哪个事件名挂在哪一格」——而动词库的好处正在这里：**不必为考据再造第四档，两个事件名共用同一档就行**。

**要做的动作**（10-17：**已建成**，落在 `crates/game_core/src/damage.rs` + `Books::damage`）：

```text
LandDamage::Degrade { levels }          // 永不动所有权 —— 类型上没有 seize 这个字段
LandDamage::Clear   { seize }           // seize=true → Owner 归 None、等级归 0、抵押一并摘
× DamageArea::One | Box { side } | Street | Whole
```

`Box` 带的是**边长**不是半径（`Box { side: 3 }` = 原表的 `Box(3)`，半径 = `(side-1)/2`），
偶数边长与 0 都不报错、只是退化成更小的方框；范围解析走 `BoardDef` 的网格坐标与 `group`
（**不复制第二份拓扑真相**，§4.2 那条红线在这儿的具体形状），2×2 的商业地按**足迹**算间隙。
`Street` 在中心那块没有 `group` 时只打自己 —— 缺配置不该扩大破坏面。

**别在各阶段分别手写"拆房"**：P3 的怪兽卡与恶魔卡、P5 的飞弹／核子飞弹／定时炸弹、P10 的工程车、P11 的外星人与山洪，全都在选组合＋选范围，实现一次就够。

两处**必须现在定、之后改很贵**的形状问题：

1. **夺地时要不要连路上的 occupancy 一起清**？核子飞弹原文说"神与物品全部消失"，但那可能是**范围**带来的、不是**夺地**带来的。我的建议：只有 `Box(3)` 及以上才顺带清 occupancy，`One`（强制征收、怪兽卡这种单块）不清——否则命运#4 会变成一次隐性清场，玩家完全看不出为什么自己身上的神没了。
   ✅ **10-17 按建议定形**：裁决写成了 `LandDamage::sweeps_tile_state(area)`（夺地 且 `Box{side>=3}` 或 `Whole` 才清），单测 `only_a_wide_seize_sweeps_the_tile_state` 钉住整张表。**P5 的 occupancy 与 P6 的附身落地时必须读这一句**，不要再各自决定一次 —— 今天它没有消费者，等的是那两个模型。
2. **定时炸弹到底动不动建筑**？原文"威力 3×3，可炸车与旁边房屋"里的"旁边房屋"含糊。建议取 `Degrade { levels: 1 } × Box(3)`、保所有权（与飞弹同格但范围略大），别让它一步归零——它是玩家放置的骚扰型道具，不是清场武器。
   ✅ **10-20 拍板：伤人 + 建筑降 1 级**，就按上面那格组合走（`Degrade { levels: 1 } × Box { side: 3 }`、保所有权）。阶梯这边不需要为它改形状，P2 因此依旧没为它写代码 —— 装配它的是 P5。§七 那行同步。

这也顺手化解了「天灾要不要做」：不用争外星人是不是 4 代的，只需要决定 `Clear{seize:true}` 这一档给不给新闻用。**我的答案：给**——那是唯一能让新闻真的吓到地产层面的档位，而新闻的存在意义就是「世界变了」而不是「你又倒霉了」。

#### 事件型收费原型（商业用地与公司企业共用，10-16 补）

「普通土地收租金、商业地产收事件费、公司企业收服务费」听起来是三套系统，实际是**同一批原型的三种装配**。你把两条公司企业的收费说成「类似旅馆」「类似加油站」，那个类比就是设计指令：**四条原型实现一次，六个载体只是选一条再填参数。**

| 原型 | 形状 | 已确认的载体 | 出处强度 |
|---|---|---|---|
| **A 随机数决定金额** | 踩到 → 摇一个数 → 按档位收钱 | 购物中心（骰 1–6） | ✅ 硬 |
| **B 随机数决定停留天数** | 踩到 → 摇一个数 → **人离场 N 天** + 付费 | 旅馆（骰 1–4，强制住宿）、人寿保险（**转盘**决定投保天数，向股权持有者付保费）、**航空**（**转盘**决定出国旅游天数 → 你补的这条） | 旅馆/保险 ✅ 硬；**航空的转盘是你给的、属新信息，但被保险的转盘结构印证** —— 4 代确实有「转盘」这件东西，不只在保险上用 |
| **C 按步数计费** | 金额 ∝ 走过的步数。**「必须开机动车才收费」不是原型的不变式，是每个载体自己的 `requires_mount` 参数** —— 油费类（加油站、中国石化）**步行完全不收**（没车就没有油耗，4 代原文就是"开车到达该点须付加油费"），而 IBM 的「电脑维修费」在主题上与车无关、资料原文也只写"按步数收费"没有"开车"二字 → ✅ **10-20 拍板：按载体填参数，油费类 `requires_mount: true`、IBM／SEGA `false`**（见 §七） | 加油站（油费，商业用地→地主收）、**中国石化／中国石油**（加油费，公司企业→董事长收）——**同一个原型在两种归属下各出现一次，这就是原型库该存在的证据**；**IBM／SEGA**（电脑维修费） | ✅ 硬。你记的 IBM 与资料原文逐字对得上（"按步数收费，大股东免费"）；**中石化／中石油的命名两边不一致**：资料侧写的是"中国石油"（大陆图的石油点），你记的是"中国石化"。不影响模型（只是 C 型再填一个参数），但**别把它当成两家不同的公司在 `stocks.json` 里造出两个 `StockId`** —— 建表时合并成一条，等真机核对再拆 |
| **D 功能型而非收费型** | 踩到不产生费用，而是解锁一个能力 | 研究所（5 级各产一种非卖道具，卖价 27/36/85/135/225）、公园（**无用**，但占地才拦得住改建卡的去处）、建设公司（远程升级任意地点） | ✅ 硬 |

**装配层只有一处是商业用地与公司企业的真差别**：

| | 商业用地 | 公司企业 |
|---|---|---|
| 土地归属 | 买地 → 选建设项 → **是自己的产业，收钱归自己** | **不能买地**，位置固定、永远是"公共"的 |
| 谁收钱 | 地主 | **持股最多者＝董事长**，他人付费、董事长免费 |
| 建造/升级 | 本人再踩一次才选；可被改建卡换类型 | 不可建造、不可改建、不可升级（等级恒为"该公司本身"） |
| 其它特权 | 无 | 百货白拿一件／银行可融资挪用他人存款／建设免费升两层／航空石油 IBM 免费；**他人取款而银行不足时从董事长扣，他人持股一旦反超则融资立刻收回** |

**这条把 P10 拆成了两件事**：先做**原型库**（A/B/C/D 各一个，收费点全部经 P2 的修正管线走，这样「董事长免费」「大财神可赖账」「加油站对步行不收费」三种豁免都只是同一个 subscriber 在不同条件下把金额改成 0），再把公司企业当成**只填装配层参数**的一批新地块。原型 B 的「离场 N 天」直接复用 P4 的 `Detention{place: Away}`——**出国旅游、被绑架、住院、坐牢在这套模型里是同一件事的四种名字**。

✅ **10-20 已拍板（形状问题，不是考证）**：**「按步数计费」的步数＝本回合掷出的点数**。IBM/加油站/石油三家原文都只写"按步数收费"，没给口径。选点数而不是「从上次收费到现在走过的总步数」，因为后者会把 C 型变成一个**需要记账的滑动窗口**，P15 存档因此要多存一份状态，而玩家在踩到之前算不出自己要付多少，收费从"可预判"退化成"事后惊讶"。**实现上它免费**：`DiceRolled.steps` 从 P3d④b 起就保持骰面原值（永远是正的、不乘方向），C 型读它即可，不需要新字段。

## 四、实现顺序

排序原则：

1. **先修「加东西会静默失效」的地方**，再加东西。落格分派原本是四个域各自 `filter`，`Lottery`/`GodDeity`/`Hospital` 踩上去什么都不发生也不报错 —— 而 `landing.rs` 的注释正承诺着相反的事。**P1 已改成一张穷尽表**（`landing::domain_of`）：新增 `TileKind` 没回答「归哪个域」就编译失败，被点名成 `Unimplemented` 的格踩上去 `warn!` 一句。P7/P10/P11 再加格类型时，这条是它们的地基。
2. **两个货币与挂点前置**：点券（P1）、修正管线+效果动词库（P2）。物价指数并进 P2 一次做完，比之后逐条改金额便宜一个数量级。
3. **命运 / 新闻 / 魔法屋不各写一套效果** —— 4 代这三池的动词大面积重叠，所以 P2 建一份**共用的效果动词库**（发钱/扣钱/离场/拆房/征收/变卖/停牌/触发拍卖/改地价），三个来源只是「谁触发 × 作用于谁 × 可否被抵消」的包装。这件事在 P2 做省下的重复，是后面三个阶段各自一遍。
4. **每阶段必须自己产出「玩家能玩到」的东西**，不留半截。纯表现层、与 core 只有一条接口的（小游戏）可并行插队。

**管线为什么是数据而不是消息订阅**：`ChargeRequested` 之前插一条 subscriber 链听起来更"架构"，但消息在**帧末**才投递，而租金那一笔必须同帧扣完（付不起就要当场破产）。所以 `Corrections` 是一张 `Vec<Correction>` 登记表 + 一个纯函数 `stage(charge, index, &corrections)`：P3/P6 只往表里 push，链本身不动 —— 测试 `register`/`cancel_for`/`scale_for` 三个helper 加修正而不碰 `charge.rs` 一眼，就是这条设计的验收。`stage` 只读 `base` 不读 `amount`，所以**幂等**：柜台报价与实际扣款读的是同一个数，重复过一遍链不会二次缩放。

**边界（说清哪些钱不过管线）**：地价、租金、升级费、罚金、奖金、神明金额过；**股价、存取款、借贷、分红、利息不过**。理由不是"忘了写"，是这些是**比率**而不是**账单**——把存款利息乘上物价，等于让通胀自己追着钱跑一遍。豁免表 `scales_with_price` 是一张穷尽表（`God => false`，其余 `true`），新增 `ChargeKind` 漏写分支＝编译失败。

**指数的分子为什么乘旧指数**（`estate_value × previous`）：地块按「名义价 × 上一次指数」估值，这样**任何一笔成交都不改变全场总资产**，指数才不会自我放大。直接拿名义价当分子的话，物价 2 倍时买一块地就凭空多出一倍资产，下一回合指数再涨——那是会跑飞的那种错。稳定性写在 `economy::price_index` 的文档里，中性有 `buying_at_the_scaled_price_is_value_neutral` / `upgrading_is_value_neutral_too` 两条纯函数测试钉住。⚠️ 集成层**不**中性：机会/命运卡是从系统外发钱，一局跑下来指数会缓慢上漂（截图那张 `物价 ×1.02` 就是 29 回合的漂移），这是玩法本来的形状，所以那条断言只在纯函数层。

**利率跟着改成月息**：`deposit_rate 0.03→0.10`、`loan_rate 0.08→0.15`。PLAN §三 那句「月末发 10% 储金利息」是月口径，而原来的数是每回合口径。**贷款必须高于储金**，否则「借满→存进银行」是无风险套利，而规则层没有任何东西挡得住它 —— 这次改口径时正好把它们拧反过一次，所以留了 `borrowing_to_deposit_earns_nothing` 这条网。

**落地记录（P3c②，10-19）**：免费卡落在一句话上 —— **「这笔账值不值得免」得由玩家判断，而不是系统替他判断**。所以它不是「免一次租金」，是「存着等那笔大的」：打出去那一刻什么都不发生。为此管线加了 PLAN 当初点的那两样：

- `Correction::floor`（名义门槛）与 `Correction::one_shot`。两个位挂在**登记条目**上而不是塞进 `Adjustment::Cancel{..}`：`one_shot` 是寿命不是算术，而嫁祸卡（`TransferTo`，同样是打一张用一次）将来读的就是同一个位。
- `stage` 拆成两个入口：`stage` 只回金额（报价侧走这条），`stage_and_spend` 额外回报 `Vec<Spent{at, saved}>`。**P3a 那条「`quoted` 不许花卡」的纪律从注释升级成返回类型** —— 报价侧连下标都拿不到，结构上花不了卡。注销在 `Books::settle`（`Corrections::spend`：倒序删，越界跳过）。

四个决定要留字：

- **「生效」的判据是「这一条有没有改变金额」，不是「有没有走到这一条」**。两张免费卡挂在同一个人身上时，第一张把 3000 免成 0，第二张走到这里什么都没改 —— 于是它没被花掉。写成「`Cancel` 一律算生效」就是烧两张卡，而那件事只会以「我的卡呢？」的形式回到玩家身上。
- **门槛跟着物价乘**（`amount > floor × 物价`）。钉死 2000 的话，物价 2 倍时这张卡连一格空地都免得掉，成了永久免费券 —— PLAN §三 那句「>2000×物价」里的乘号是玩法，不是排版。
- **`ChargeDomain::Property` 拆成 `Rent` 与 `Acquire`**。免费卡免的是过路费与罚款，而「买地免费」是大福神的特权（§三 神明行）—— 两族钱挤在一个域里就写不出这个区别；P10 的「董事长本人免费」本来也只吃 `Rent`。顺带 `Scope` 添了复数那一格：一张卡管两族钱（租金+罚金）若登记成**两条**，一次生效会烧掉两张。
- **免付发新凭据 `ChargeWaived{player, saved, via}`，不发 `CashChanged`**：这里没有钱动。把「少付 2400」记成 `+2400` 会让 B3 那条现金审计（余额 == 起始 + Σ delta）对不上，而那正是 P1 立两套账的理由。顶栏那一行读的就是它 —— 「租金那一格显示 0」不等于「玩家知道自己刚花掉一张卡」。

## 五、两个新格子的设计

### 点券格（P1）

```json
{ "id": 5, "col": 3, "row": 1, "type": "coupon", "name": "点券箱", "data": { "coupon": 30, "refresh": 6 } }
```

**三种固定面额，不随机抽。** 关于你提的「随机抽也有 ±20 的不确定感」——对平衡的影响确实小，但代价不在平衡上：

- 随机抽让三档的**期望值全部变成 30**，「三种面额」这个设计本身当场被消解；
- 更强的那条是**地图可读性**：4 代把 10/30/50 排成一段梯度、和小游戏格同处一段，等于在地图上写出「**这一段路值得走**」。玩家两三回合内学会「我离那段路还差 4 步」，这才是路线规划乐趣的最小单元，也是转向卡/遥控骰子存在的理由。随机抽把这条路降级成期望值恒等的装饰。

而你要的**不确定感，4 代本来就有另一个来源**：路上的点券箱/宝箱是**一次性拾取**（开局抢第一只宝箱是 4 代玩家的真实核心战术）。所以：

| 机制 | 取值 |
|---|---|
| 面额 | **10／30／50 固定**，数据决定 |
| 排布 | **连续一段（梯度递增）+ 与小游戏格同段**，照原作 |
| 一次性 | **踩了就没**，`refresh` 回合后重新出现（默认 6） |

不确定感于是来自「**谁先抢到这一段、下一轮什么时候刷新**」，而不是抽到几——这是争夺，不是抽奖，比随机抽更有味道。

实现上「一次性 + 冷却」不需要道路格实体：一个 `HashMap<TileIndex, ReadyAtTurn>` 资源即可（这条与 P5 的 occupancy 是两件事，别提前建那套）。日后确实想加随机档，再加一个独立的 `coupon_random: [u32]` 字段——让「赌博感」单独住在一个格子里，不污染三档梯度。

**落地记录（P1，10-16）**：`CouponBoxes` 资源就是那个 map，冷却读 `GameSession::turn_count`（全场合计的回合数，与「一天一回合」同口径）。结算不挂 `Pending` —— 捡箱子没有「要不要」这个决策，弹一张收据只会把回合机停在没人回答的地方。演示盘 prototype 的 10 号格（原「中央银行」）改成了 `coupon`/面额 30：12 格里没有能腾出「连续一段梯度」的余量，**三档排布留给真棋盘**，这里只保证机制在真对局里看得见（HUD 有「点券:N」一段、顶栏会报「捡到 30 点券」）。第二块银行是被拿掉的那一格——ATM 与柜台都还需要，但 6 号那一块就够。

### 小游戏格（P7）

```json
{ "id": 8, "col": 4, "row": 2, "type": "arcade", "name": "游乐场", "data": { "game": "pop_balloons" } }
```

- `TileKind::Arcade` + `TileData.game`（`pop_balloons`／`catch_treasure`／`penguin_dig`）。三种共用一个格类型、靠 `game` 分流——不各开一个 `TileKind`，否则格类型被美术资产数量污染。
- **core 不实现玩法本体**（AGENTS.md 硬约束第 2 条的精神）：core 只管「这格开一局、把回合挂住、拿分数、换点券」。接口一进一出：`Pending::Minigame(GameKind)` ← → `MinigameScore { player, game, score, awarded }`。
- **成绩→点券映射表进 `GameRules`**，三种各配满分与斜率。理由：这三种游戏的平衡是这功能唯一真正难的地方，参数必须在同一张表里能横向比较。
- 主菜单练习局不给点券（4 代原规则），且**用 `awarded: bool` 显式表达**，不靠「主菜单不发消息」隐式实现——隐式的奖励开关是最难查的一类。
- 挂点：小游戏跑在 `WaitDecision`，所以它是第六种 `Pending`。[landing.rs:147-179](../crates/game_core/src/landing.rs#L147) 那个 `match (about, action)` 是真穷尽的，编译器会要求补分支。

### 新闻中心格（P11，形状先记在这里）

```json
{ "id": 2, "col": 2, "row": 1, "type": "news", "name": "新闻中心", "data": {} }
```

- 一张图**一格**（4 代口径），谁踩谁开广播。
- **不做成「随机抽一条」的黑盒**：新闻数据要和命运同构（`data/news_items.json`，每条带 `scope` + `effects` + `days`），这样它天然复用 P2 的动词库，且玩家能读到文案、策划能改数值。
- 抽取算法 4 代**没有任何记载**（无顺序、无权重、无冷却的出处），所以这块是我们的自由设计：✅ **10-20 拍板＝全池随机 + 同一场次内不连抽同一条**。别学命运做定序——「可数」是命运的玩法，新闻的乐趣正是「不知道下一条是福是祸」。这条只多一个状态（`GameSession::last_news`），代价已写进 §四 的 P11 与 P15 两行。
- 数值 4 代原文全是「…元／百分之几／……天」占位符，**公开资料扒不出常数**，得自己定并写进 `GameRules`。

- **egui dump 面板提前到 T1**（P1 之后、P2 之前）。✅ **10-20 拍板追认，且它在 10-16 已经落地**。它不是玩法阶段，但它是 ARCHITECTURE §十一 那条 10-13 拍板、核对时发现**从未落地**的账；而 P2 是全计划第一个「数值为什么是这样」无法从画面反推的阶段。位置的理由写在 §四 表里那行说明。
