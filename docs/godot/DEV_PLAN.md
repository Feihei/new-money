# 《暴富》开发计划

> 基于 Godot 4.7 的大富翁4风格模拟经营棋类游戏
> 文档版本：v1.2 ｜ 目标平台：Windows / macOS / Linux（后续可移植移动端）

---

## 一、项目概述

### 1.1 游戏定位
复刻并现代化《大富翁4》的核心体验：在环形棋盘上掷骰移动，通过购买/升级地产、买卖股票、触发随机事件积累财富，最终使对手破产。

### 1.2 核心玩法循环
```
掷骰 → 移动 → 落格触发 → 经济决策 → 结算回合 → 下一玩家
								↑
						(股票/卡牌随时可操作)
```

### 1.3 差异化目标
- 保留大富翁4的"股票+地产+角色技能"三角经济
- 现代化 UI（响应式、动画流畅）
- 支持本地多人 + 在线联机（远期）
- 模组友好（棋盘/卡牌/角色数据驱动）

## 三、技术架构

### 3.1 引擎配置（已在 project.godot 中）
- 渲染器：Forward+（D3D12，支持 3D 渲染）
- 物理：`2d/physics_engine="Dummy"`、`3d/physics_engine="Dummy"`（已禁用，棋类游戏无需物理）
- 渲染管线：3D 正交等轴测渲染 + CanvasLayer 2D UI 叠加（根节点 `Node3D`）
- 分辨率策略：`canvas_items` + `expand`（适配多分辨率）

### 3.2 推荐目录结构（已就绪）
```
res://
├── scenes/              # 场景文件
│   ├── board/           # 棋盘主场景
│   ├── ui/              # UI 场景
│   └── entities/        # 玩家、棋子、格子
├── scripts/
│   ├── core/            # 核心游戏逻辑（无 UI 依赖）
│   │   ├── game_state.gd
│   │   ├── turn_manager.gd
│   │   ├── board_model.gd
│   │   ├── economy.gd
│   │   └── stock_market.gd
│   ├── systems/         # 功能系统
│   │   ├── property_system.gd
│   │   ├── card_system.gd
│   │   ├── event_system.gd
│   │   └── ai_controller.gd
│   ├── ui/              # UI 控制器
│   └── autoload/        # 单例
├── data/                # 数据驱动配置（JSON/Resource）
│   ├── boards/
│   ├── cards/
│   ├── stocks/
│   └── characters/
├── assets/
│   ├── sprites/
│   ├── audio/
│   ├── fonts/
│   └── ui/
├── tests/               # GUT 单元测试
└── addons/gut/          # 已安装
```

### 3.3 架构原则
1. **MVC 分层**：`core/` 是纯逻辑模型，`ui/` 只负责展示，`systems/` 是协调层
2. **数据驱动**：棋盘、卡牌、股票、角色全部用 `Resource` 或 JSON 配置，硬编码零容忍
3. **事件总线**：用 `EventBus` 单例解耦系统间通信
4. **状态机**：回合流程用 FSM，避免面条代码
5. **可测试**：核心逻辑全部可脱离场景跑 GUT 测试

### 3.4 2.5D 渲染架构（Phase 1.5）

Phase 1.5 已将渲染层从 2D 迁移为 **45° 等轴测正交 3D（OrthographicCamera3D + Node3D）**。

**场景结构**（`board.tscn`）：
```
Board (Node3D)                    ← 根节点必须是 Node3D 才启动 3D pass
├── Board3D (Node3D)              ← 棋盘 3D 世界
│   ├── CameraRig (Node3D)        ← XZ 跟随 token，相机固定偏移
│   │   └── BoardCamera (Camera3D)← 本地 (8,16,8)，正交投影
│   ├── DirectionalLight3D
│   ├── BoardPath (Path3D)        ← Curve3D 环形路径
│   └── TilesContainer (Node3D)   ← TileView 实例
├── BGLayer (CanvasLayer, -1)     ← 空（背景由 Camera3D Environment 提供）
└── UILayer (CanvasLayer, 1)      ← UI 叠加在 3D 之上
```

**关键约定**：
- 数据/逻辑层（`BoardTile`/`BoardData`/`Dice`/`EventBus`）不依赖渲染维度，100% 复用
- 棋子移动：`PathFollow3D.progress_ratio` + Tween 逐格（与 PathFollow2D 同名 API）
- UI：始终走 `CanvasLayer` Control，不直接混在 3D 节点下
- Z 遮挡：由 3D 深度缓冲自动处理，无需手动 `z_index`

**目标**：棋盘能显示，棋子能按骰子点数移动

- [x] 设计格子数据结构（`BoardTile` Resource：类型、坐标、关联数据）
- [x] 实现环形棋盘渲染（`Path2D` + `PathFollow2D` 做移动轨迹）→ Phase 1.5 已迁移为 `Path3D`
- [x] 棋子沿路径移动动画（Tween 逐格推进，每格 180ms，落格弹跳）

**技术要点（原始 2D 方案，Phase 1.5 已改为 3D）**：
- 用 `Path2D` 画环形路径，`PathFollow2D.progress_ratio` 控制棋子位置
- 移动用 `Tween` 逐格推进，每格 ~180ms
- 棋盘坐标用格子索引（0~N-1），渲染时再映射到像素
- ⚠️ 注意：原计划用 `TileData` 类名，与 Godot 4.7 原生类冲突，已改名 `BoardTile`

**交付物**：能掷骰子，棋子沿环形棋盘走相应步数 ✅

### 阶段 1.5：渲染层 2.5D 等轴测改造（1-2 天）✅ 已完成
**目标**：将 2D 渲染层替换为 45° 等轴测正交 3D 渲染，正确处理 Z 深度遮挡

- [x] 场景结构：`board.tscn` 根从 `Control` 改为 `Node3D`，3D 节点（`Camera3D`/`Path3D`/`TilesContainer`）预置在 tscn
- [x] 棋盘：`Path2D`/`Curve2D` → `Path3D`/`Curve3D`（XZ 平面圆角矩形环，80×60 单位）
- [x] 格子：`Node2D`/`ColorRect`/`Label` → `Node3D`/`MeshInstance3D`/`Label3D`（unshaded 材质）
- [x] 棋子：`PathFollow2D` → `PathFollow3D`（`progress_ratio` 同名，移动逻辑原样搬）
- [x] 相机：`Camera2D` → `Camera3D`（正交投影）+ CameraRig 跟随 token（平滑 Tween）
- [x] UI：`CanvasLayer` 分离，UILayer 叠加在 3D 之上不受影响
- [x] Z 遮挡：由 3D 深度缓冲自动处理，无需手动 `z_index`

**技术要点**：
- 相机用 CameraRig 方案：Rig XZ 跟随 token，相机本地 `CAM_OFFSET` 固定偏移 + `look_at(0,0,0)`
- 关键常量（`board.gd`）：`CAM_OFFSET = (8,16,8)`，`CAM_SIZE = 25`（建议改为 35 缓解移动晕眩）
- 材质全 `unshaded`，无光照依赖；背景色用 `Environment(BG_COLOR)`
- ⚠️ Godot 4.7 踩坑：根必须 `Node3D`、`CanvasLayer ColorRect` 盖 3D、`Camera3D.projection` 不是 `projection_mode`

**交付物**：等轴测棋盘 + 棋子 + 相机跟随，GUT 38/40 ✅

## 六、注意事项 ⚠️

### 6.1 设计层面

1. **数值平衡是命门**
   - 大富翁4的乐趣来自经济曲线，开局要慢、中盘要乱、终局要爽
   - 建议用 Excel 建模模拟 100 局，调参后再写代码
   - 股票波动率、地产租金、起始资金三者要联动调

2. **避免"一回合操作过载"**
   - 玩家一回合能做的事要克制（掷骰 + 1-2 次经济操作）
   - 否则单回合思考时间过长，AI 与玩家都累

3. **随机性要有上限**
   - 机会卡不能纯随机毁灭玩家，加"保底机制"
   - 神仙附身要有解法（道具、特定格子）

4. **破产判定要明确**
   - 现金 < 0 且无法变现 → 破产
   - 资产清算顺序：股票 → 地产抵押 → 地产出售 → 退出

### 6.2 技术层面

1. **Godot 4.7 兼容性**
   - 4.x 系列 API 稳定，但 4.7 是较新版本，部分第三方插件可能未适配
   - 安装插件前先看其支持的 Godot 版本
   - 建议锁定 4.7.x，避免每次小版本升级踩坑

2. **Jolt 物理对本项目无用**
   - 棋类游戏几乎不用物理，可考虑改用无物理或禁用，省内存
   - 在 project.godot 中 `physics/3d/physics_engine="none"` 或保留但不创建物理体

3. **数据驱动优先**
   - 千万不要把棋盘、卡牌硬编码在脚本里
   - 用 `Resource` 或 JSON，后期改平衡只改数据不改代码
   - 这是大富翁类游戏可维护性的关键

4. **状态机要严谨**
   - 回合流程涉及大量异步（动画、AI 思考、玩家输入）
   - 用 FSM + 信号，避免回调地狱
   - 每个状态进入/退出时做断言，防止状态错乱

5. **存档要早做**
   - 不要等最后才做存档，核心数据结构一开始就要可序列化
   - 避免用 `Object` 引用难以序列化的字段
   - 存档加版本号，预留迁移接口

6. **AI 不要阻塞主线程**
   - AI 决策可能耗时，用 `await` 分帧或放 `WorkerThread`
   - 加伪延迟（500-1500ms）让玩家能跟上节奏

7. **多人联机的坑**
   - 如果做联机，**从第一天就用 RPC 友好的架构**：所有状态变更走 `EventBus`，确定性强
   - 后期改联机成本极高，最好单机做好再考虑

8. **性能**
   - 棋盘格子不多（~40），性能不是瓶颈
   - 注意 UI 重绘（K 线图、飘字），用 `call_deferred` 与对象池

### 6.3 项目管理层面

1. **先做垂直切片**
   - 不要先做完所有格子再做地产，而是**先做一个最小可玩对局**
   - 2 玩家、8 格棋盘、买地收租，跑通全程
   - 再逐步扩充。这是降低风险的关键

2. **测试驱动核心逻辑**
   - 已装 GUT，把收租、股价、破产判定这些纯逻辑写成测试
   - UI 不用测，但数值与状态机必须测

3. **版本控制**
   - Godot 场景是文本，但 `.tscn` 合并冲突痛苦
   - 建议：场景拆细，每人/每次改动只动一个场景
   - `.godot/` 目录加 `.gitignore`

4. **美术版权**
   - 不要直接用大富翁4的美术/音乐，会侵权
   - 风格可以借鉴，资产必须原创或合规授权

5. **范围控制**
   - 大富翁4有 12 个角色、多张地图、股票、神仙……内容量巨大
   - MVP 先做 4 角色、1 地图、核心系统
   - 用"是否影响核心循环"判断功能优先级

- **玩法**：玩法不受版权保护，可放心借鉴
- **发行**：Steam 上架需 100 美元保证金；移动端需适配触控
